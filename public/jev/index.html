Anti-pattern

Choice as a decision: “Which model should I use?”

Why this is worse

  • Jev makes the decision. Cost, speed and quality trade-offs are policy, and they live inside the model instead of in code you can read and test.
  • The options are just labels. “Claude Opus” describes nothing Jev can match against the prompt, so the answer depends on what Jev happens to know about each model.
  • It fails the human test. A smart person shown only this prompt would ask, “what do you care about, cost or quality?”
  • There’s nothing to change but the wording. No reasoning level, no thresholds, no rules to read. Changing policy means rewriting the question.

Choice: Rock, Paper, Scissors

Jev is asked one question each round: given the rounds so far, what would an ordinary person in its seat throw next? It answers with a Choice over rock, paper and scissors, and plays the top option. It never sees the throw you just made.

    Jev isn’t given any strategy. Habits like opening with rock or repeating a win come from its own sense of how people play. Each round is one Jev call.

    API call

    The Jev model version.

    The content to evaluate: the rounds so far, with each side’s throw and the winner.
    questions
    One per judgment, keyed by your ID (next_throw).
    type
    Always "choice".
    instructions
    The question the model answers.
    criteria
    The answer options, each with a description.
